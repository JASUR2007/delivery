# Договор поставки: Учет штрафов и Бухгалтерия

Веб-приложение для ведения государственных договоров закупки товаров, расчета неустойки при задержке поставки и сквозного бухгалтерского учета (поэтапные платежи, контроль остатков помесячной сметы, реестр и регламент отмены платежей).

Проект разработан на **Laravel 12** + **Inertia.js (React + Tailwind CSS)** с использованием чистой архитектуры (Senior Architecture: DTO, Services, Repositories, FormRequests, API Resources, Policies, Enums).

---

## Быстрый запуск

### 1. Установка зависимостей
```bash
composer install
npm install
```

### 2. Настройка окружения
```bash
cp .env.example .env
php artisan key:generate
```

### 3. Инициализация базы данных и сборка фронтенда
```bash
php artisan migrate:fresh --seed
npm run build
```

### 4. Запуск локального сервера
```bash
php artisan serve
```

Приложение доступно в браузере по адресу: **http://localhost:8000** (или **http://localhost:8080**)  
При первом переходе неавторизованный пользователь перенаправляется на страницу входа `/login`.

## Автоматизированные тесты

В проекте реализованы 38 функциональных и модульных тестов, полностью покрывающих требования технического задания:
- Точный расчет неустойки (Пример 1: 3 дня задержки = 37.50; Пример 2: частичная поставка 14 марта = 35.00).
- Проверка ограничения штрафа 50% от суммы непоставленного товара на дату дедлайна (Cap).
- Проверка нулевого штрафа при расчете до или в день дедлайна.
- Процедура утверждения штрафа руководителем (по номиналу и с изменением суммы).
- Отображение штрафа в бухгалтерии строго после утверждения (при статусе pending или rejected штраф равен 0.00).
- 5 обязательных проверок бухгалтерии при внесении платежа в строгой последовательности.
- Реестр платежей, регламент отмены (voiding) с обязательной причиной и перерасчет балансов сметы и этапов.
- Серверный контроль прав доступа (Gate/Policy): исполнитель не может открыть чужой договор по прямому ID.
- Конкурентность: пессимистическая блокировка строк (`lockForUpdate`), исключающая уход сметы в минус при параллельных запросах.
- Работоспособность интерфейса Swagger UI и эндпоинта OpenAPI JSON.
