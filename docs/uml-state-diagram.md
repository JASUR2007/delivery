# UML State Machine Diagrams (Диаграммы состояний)

Диаграммы конечных автоматов демонстрируют жизненный цикл ключевых доменных сущностей системы: договоров, этапов оплаты, штрафов и платежей.

---

## 1. Жизненный цикл договора (Contract Lifecycle)

```mermaid
stateDiagram-v2
    [*] --> Draft: Исполнитель создает договор

    state Draft {
        [*] --> ДобавлениеСтрок: Минимум 1 товарная строка
        ДобавлениеСтрок --> ГотовКАктивации
    }

    Draft --> Active: Исполнитель активирует договор (Activate)
    note right of Active
        После активации:
        - Условия и строки неизменны
        - Генерируются этапы оплаты (Аванс 30%, Поставка 70%)
        - Открыт прием партий товаров
    end note

    Active --> Completed: Все платные товары поставлены на 100%
    note right of Completed
        Автоматический переход:
        arePaidGoodsFullyDelivered() === true
        Бонусный товар на завершение не влияет
    end note

    Completed --> [*]
```

## 2. Жизненный цикл этапа оплаты (Payment Milestone)

Статус этапа не меняется пользователем вручную — он динамически вычисляется движком на основе фактических данных реестра и поставок:

```mermaid
stateDiagram-v2
    [*] --> Planned: Создан при активации договора

    Planned --> ReadyToPay: Условие этапа выполнено
    note right of ReadyToPay
        - Аванс: сразу после активации договора
        - Поставка: после 100% приемки платного товара
        - Предыдущий этап должен быть оплачен
    end note

    ReadyToPay --> PartiallyPaid: Внесен частичный платеж (0 < Сумма < Остаток)
    ReadyToPay --> Paid: Внесен платеж на весь остаток (Остаток = 0.00)

    PartiallyPaid --> Paid: Внесен доплатный платеж на остаток
    
    ReadyToPay --> Overdue: Наступил дедлайн (due_date < asOfDate) и есть остаток
    PartiallyPaid --> Overdue: Наступил дедлайн при наличии долга

    Paid --> PartiallyPaid: Бухгалтер аннулировал финальный платеж (Void)
    PartiallyPaid --> ReadyToPay: Бухгалтер аннулировал первый частичный платеж (Void)
```

## 3. Жизненный цикл штрафа (Penalty Approval Lifecycle)

```mermaid
stateDiagram-v2
    [*] --> Calculated: Система рассчитывает неустойку на дату (0.5% в день)

    Calculated --> Pending: Фиксация расчета для утверждения

    Pending --> Approved: Руководитель утверждает штраф
    note right of Approved
        Руководитель может утвердить:
        - Расчетную сумму
        - Скорректированную сумму (с обоснованием)
        Только Approved штраф учитывается в бухгалтерии!
    end note

    Pending --> Rejected: Руководитель отклоняет штраф (с причиной)
    note right of Rejected
        Штраф обнуляется и не удерживается в бухгалтерии
    end note

    Approved --> [*]
    Rejected --> [*]
```

## 4. Жизненный цикл платежа (Payment Lifecycle)

```mermaid
stateDiagram-v2
    [*] --> Completed: Бухгалтер провел платеж (5 проверок пройдены)
    
    note right of Completed
        - Средства списаны со сметы месяца
        - Остаток этапа уменьшен
        - Запись зафиксирована в реестре
    end note

    Completed --> Voided: Бухгалтер аннулировал платеж
    
    note right of Voided
        Правило неизменяемости:
        - Запись НЕ удаляется из базы
        - Фиксируется автор, дата и причина отмены
        - Остаток сметы и этапа автоматически восстанавливается
    end note

    Voided --> [*]
```
